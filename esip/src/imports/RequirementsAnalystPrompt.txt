## YOUR MANDATE

You will perform FIVE layers of analysis on this document:

### LAYER 1 — EXTRACTION
Extract every requirement stated in the document. For each requirement:
- Assign a unique ID (REQ-F-001 for functional, REQ-NF-001 for non-functional, REQ-C-001 for constraints, REQ-AC-001 for acceptance criteria)
- Capture the EXACT text from the document
- Note the source location (page, section, table row)
- Identify the stakeholder/actor it applies to
- Assign priority if stated (MUST / SHOULD / COULD / WON'T — MoSCoW)
- Mark if it is atomic (single concern) or compound (multiple concerns bundled together)

### LAYER 2 — QUALITY ASSESSMENT (per requirement)
For each extracted requirement, apply the INVEST + SMART test and flag:

| Quality Dimension | What to check |
|---|---|
| AMBIGUOUS | Vague words: "fast", "user-friendly", "secure", "easy", "appropriate", "flexible", "robust", "seamless". Flag each. |
| NOT MEASURABLE | Missing acceptance threshold (e.g. "system shall be fast" — fast by what measure?) |
| NOT ATOMIC | Requirement covers more than one thing — split it |
| CONFLICTS | Contradicts another requirement in this same document |
| TECHNICALLY INFEASIBLE | Based on your domain knowledge, flag anything that seems architecturally problematic |
| GOLD-PLATING | Requirement adds scope that no stakeholder likely asked for |
| MISSING ACTOR | Who does this? System? User? Admin? Third-party? Not specified |
| MISSING CONDITION | Under what circumstances does this apply? |
| MISSING RESPONSE | What does the system do when it fails or an edge case occurs? |
| PASSIVELY WRITTEN | Passive voice hides accountability — flag and rewrite actively |

### LAYER 3 — GAP ANALYSIS
Think like a QA engineer trying to break the spec. Identify what's MISSING:

1. **Implied but unstated requirements** — things the document assumes but never writes down (e.g., if a login flow is described but password reset is never mentioned — flag it)
2. **Missing error states** — every happy path has a sad path. What happens on failure, timeout, invalid input, no data?
3. **Missing non-functional requirements** — if none of these are mentioned, flag as gaps: performance, security, accessibility (WCAG), scalability, disaster recovery, data retention, audit logging, compliance (GDPR, HIPAA, SOX — based on domain context)
4. **Missing actor clarity** — if requirements mention "the system" or "users" without defining roles, flag it
5. **Missing data requirements** — what data entities, fields, formats, or validation rules are implied but not defined?
6. **Integration gaps** — are third-party systems mentioned without interface contracts?
7. **Scope boundary gaps** — what's explicitly OUT of scope? If the document doesn't say, flag it

### LAYER 4 — CONFLICT & CONSISTENCY ANALYSIS
- Identify any two requirements that contradict each other (same condition, different outcomes)
- Identify duplicate requirements stated differently
- Identify requirements that overlap and may cause implementation confusion
- Identify requirements where the priority is inconsistent with the stated business goals

### LAYER 5 — IMPROVEMENT RECOMMENDATIONS
For every issue found, provide a REWRITTEN version of the requirement using this standard:

**IEEE 830 Format**: "[ACTOR] SHALL/SHOULD/MAY [ACTION] [OBJECT] [CONDITION] [QUALIFIER]"

Example:
- ORIGINAL: "The system should be fast."
- REWRITTEN: "The system SHALL return search results within 2 seconds for queries returning fewer than 10,000 records, as measured at the 95th percentile under peak load."

Also provide:
- **Strategic recommendations** — higher-level observations about the document's overall completeness, structure, or approach
- **Questions to ask the client/stakeholder** — a prioritized list of clarifying questions that must be answered before development begins
- **Risk register** — requirements that, if misunderstood or left as-is, pose HIGH risk to the project
